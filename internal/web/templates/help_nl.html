Hoe werkt het

Toestellen in je netwerk (printers, scanners) sturen mail naar deze relay met een vast IP-adres en een gebruikersnaam en wachtwoord. De relay stuurt de mail door naar Microsoft 365 via de Microsoft Graph API met een app-registratie. Er staat dus geen Microsoft-wachtwoord op een toestel en Security Defaults kunnen aan blijven.

Stappenplan in het kort

  1. De Microsoft Entra-app aanmaken (ongeveer 10 minuten)
  2. De gegevens invullen en de verbinding controleren
  3. Een afzender-mailbox voorzien
  4. Beperken als welke mailboxen de app mag versturen (aanbevolen)
  5. Ongeveer 5 minuten wachten
  6. Een testmail versturen
  7. Het toestel toevoegen en instellen
  8. Regels per toestel (optioneel)
  9. Beheer, meldingen en beveiliging
  10. Netwerk en HTTPS
  11. Het client secret tijdig vernieuwen

Loopt er iets mis? Zie Problemen oplossen of kijk op de pagina Logboek: fouten van Microsoft staan daar met uitleg.

1. De Microsoft Entra-app aanmaken

Je hebt een account nodig dat app-registraties mag maken en beheerderstoestemming mag geven (Application Administrator of Global Administrator). Je hebt geen Azure-abonnement en geen extra licentie nodig.

Optie A: in de portal

  1. Open entra.microsoft.com → Entra ID → App registrations → New registration.
  2. Naam: office-smtprelay. Account types: Single tenant (alleen deze map). Redirect-URI: leeg laten. Klik op Register.
  3. Kopieer van de overzichtspagina het Application (client) ID en het Directory (tenant) ID.
  4. API permissions → Add a permission → Microsoft Graph → Application permissions → zoek Mail.Send, vink aan, Add permissions. Voeg geen Delegated permissions toe.
  5. Klik op Grant admin consent for ... en bevestig. In de kolom Status moet een groen vinkje staan ("Granted for ...").
  6. Certificates & secrets → Client secrets → New client secret. Kies een vervaldatum (maximaal 24 maanden).
  7. Kopieer meteen de kolom Value van het secret. Die wordt maar één keer getoond. Kopieer niet het Secret ID.

Optie B: met het hulpscript

Het script doet stap 1 t/m 7 hierboven voor je. Het schrijft niets naar schijf: de waarden verschijnen eenmalig op het scherm.

  1. Download Setup-EntraApp.ps1 naar een Windows-pc.
  2. Open een gewoon PowerShell-venster (geen ingebouwde terminal: het aanmeldvenster heeft een bovenliggend venster nodig) en voer uit:
Install-Module Microsoft.Graph.Applications -Scope CurrentUser   # eenmalig
.\Setup-EntraApp.ps1                    # interactief aanmelden
.\Setup-EntraApp.ps1 -SecretMonths 12   # kortere levensduur van het secret
.\Setup-EntraApp.ps1 -SkipConsent       # app maken, toestemming zelf geven (zie stap 4)

Meld aan met een beheerdersaccount en keur de gevraagde rechten goed. Bij een foutmelding over uitvoeringsbeleid: Set-ExecutionPolicy -Scope Process Bypass in datzelfde venster.

2. De gegevens invullen en de verbinding controleren

  1. Open de pagina Microsoft 365.
  2. Vul Tenant ID, Application (client) ID, het client secret en de vervaldatum in en klik op Opslaan. De vervaldatum is optioneel, maar dan waarschuwt het dashboard je 30 dagen vóór het secret verloopt.
  3. Klik op Verbinding controleren. Groen betekent dat Microsoft de drie gegevens aanvaardt. Dit test nog niet of er daadwerkelijk mail verstuurd mag worden.

3. Een afzender-mailbox voorzien

  • Het afzenderadres van een toestel moet een bestaande mailbox in je tenant zijn, bijvoorbeeld printer@jouwdomein.be.
  • Een gedeelde mailbox (shared mailbox) volstaat en heeft geen licentie nodig (tot 50 GB). Aanmelden op die mailbox hoeft niet aan te staan en SMTP AUTH ook niet: de relay meldt nooit aan als die mailbox.
  • Verstuurde mails komen in Verzonden items van die mailbox. Bij veel mail kan die volgelopen raken: stel eventueel een bewaarbeleid in.
  • Zorg dat SPF, DKIM en DMARC van je domein in orde zijn, zoals voor alle andere uitgaande mail.

Een gedeelde mailbox maak je in het Exchange admin center (Recipients → Mailboxes → Add a shared mailbox) of in Exchange Online PowerShell:

Connect-ExchangeOnline
New-Mailbox -Shared -Name "Printer" -DisplayName "Printer" -PrimarySmtpAddress printer@jouwdomein.be

4. Beperken als welke mailboxen de app mag versturen (aanbevolen)

Zonder beperking laat Mail.Send (applicatierecht) de app versturen als elke mailbox in je tenant. Lekt het secret, dan kan iemand mailen als eender wie in je organisatie. Met Exchange Online RBAC for Applications beperk je dat tot de mailboxen die je kiest. Bij een kleine tenant met een vertrouwd netwerk mag je deze stap overslaan.

Je hebt ook de rol Exchange Administrator nodig. De Object ID van de service principal vind je in Entra onder Enterprise applications → office-smtprelay → Overview (let op: niet de Object ID van de app-registratie).

  1. Maak een mail-ingeschakelde beveiligingsgroep (bijvoorbeeld smtp-relay-senders) in het Exchange admin center en voeg de afzender-mailbox(en) toe als lid.
  2. Voer in Exchange Online PowerShell uit en pas de waarden aan:
Connect-ExchangeOnline

$appId = '<Application (client) ID>'
$spId  = '<Object ID van de ENTERPRISE APPLICATION (service principal)>'

# 1. De service principal in Exchange registreren
New-ServicePrincipal -AppId $appId -ObjectId $spId -DisplayName 'office-smtprelay'

# 2. Een bereik (scope) maken met de toegelaten mailboxen
$group = Get-DistributionGroup 'smtp-relay-senders'
New-ManagementScope -Name 'SmtpRelaySenders' `
  -RecipientRestrictionFilter "MemberOfGroup -eq '$($group.DistinguishedName)'"

# 3. De app enkel voor dat bereik laten versturen
New-ManagementRoleAssignment -App $spId -Role 'Application Mail.Send' -CustomResourceScope 'SmtpRelaySenders'

# 4. Controleren (wacht eventueel enkele minuten)
Test-ServicePrincipalAuthorization -Identity $spId -Resource printer@jouwdomein.be        # InScope = True
Test-ServicePrincipalAuthorization -Identity $spId -Resource iemand-anders@jouwdomein.be  # InScope = False
  1. Trek daarna de tenantbrede Graph-toestemming in, zodat enkel de beperkte Exchange-toewijzing geldt: Entra → Enterprise applications → office-smtprelay → Permissions → verwijder de toestemming voor Mail.Send. (Maakte je de app met het script, gebruik dan de volgende keer -SkipConsent.)

5. Ongeveer 5 minuten wachten

Nieuwe toestemmingen en rechten werken bij Microsoft niet meteen. Reken op ongeveer 5 minuten, soms tot 30 minuten bij Exchange-rolwijzigingen. Een testmail die direct na het instellen faalt, betekent dus niet dat er iets fout staat: wacht even en probeer opnieuw.

6. Een testmail versturen

  1. Open de pagina Testmail.
  2. Kies als afzender de mailbox uit stap 3 en als ontvanger je eigen adres. Probeer later ook een extern adres.
  3. Controleer of de mail binnenkomt en niet in de ongewenste mail belandt.
  4. Mislukt het? De foutmelding staat op het scherm én op de pagina Logboek (toestel "web UI"), met uitleg wat je kan doen.

De testmail gaat rechtstreeks naar Microsoft en test dus de Microsoft-kant, niet het toestel.

7. Het toestel toevoegen en instellen

  1. Geef het toestel eerst een vast IP-adres in je router.
  2. Voeg het toe op de pagina Toestellen met dat IP-adres. Het wachtwoord dat daarna verschijnt, wordt maar één keer getoond: noteer het meteen.
  3. Voer deze instellingen in op het toestel:
SMTP-server
{{.Data.Host}}
Poort
{{.Data.Port}}
Beveiliging
STARTTLS
Authenticatie
Vereist (PLAIN of LOGIN) met de gebruikersnaam en het wachtwoord van de pagina Toestellen
Afzenderadres
De bestaande mailbox uit stap 3
  1. Stuur vanaf het toestel een testbericht. Mislukt dat, bekijk dan Logboek: elk geweigerd bericht staat er met de reden.

De relay gebruikt standaard een zelfondertekend certificaat. Weigert het toestel dat, zet dan de certificaatcontrole op het toestel uit of voorzie een eigen certificaat. Zeer oude toestellen die geen TLS 1.2 kunnen, vragen de serverinstelling SMTPRELAY_TLS_MIN.

Regels per toestel (optioneel)

De relay is geen open relay: een toestel moet een bekend IP-adres hebben én inloggen. Daarbovenop kan je per toestel extra regels instellen via Toestellen → Regels. Er is niets verplicht: een toestel zonder regels werkt zoals altijd.

  • Afzender: toelaten van bepaalde adressen, of de afzender herschrijven naar één adres. Herschrijven weigert nooit en is ideaal voor printers die hun afzender niet kunnen instellen.
  • Ontvangers: enkel interne adressen (je eigen domeinen), of een eigen lijst. Een gekaapt toestel kan dan geen spam naar buiten sturen.
  • Limieten: berichten per uur en per dag, ontvangers per bericht, maximale grootte. Bij overschrijding wordt het bericht uitgesteld, of het toestel enkele minuten geblokkeerd.
  • Aanpassingen: een vast Reply-To-adres en een voorvoegsel in het onderwerp.
  • Noodknop op het overzicht: pauzeert alle verzending in één keer. Toestellen proberen later opnieuw.

Zo ga je veilig te werk: zet een nieuwe regel eerst op Testmodus. Overtredingen worden dan alleen gelogd (Logboek, filter Regeloverschrijdingen) en niets wordt geblokkeerd. Zie je na een paar dagen dat de printer zich aan de regel houdt, zet de regel dan op Aan.

Beheer, meldingen en beveiliging van de interface

  • Meldingen: een korte mail bij problemen met Microsoft 365, een bijna verlopen secret, een geblokkeerd toestel of een pauze. Staat standaard uit.
  • Verbinding: het TLS-certificaat vervangen (uploaden of opnieuw zelf laten maken), de oudste toegelaten TLS-versie, en extra poorten (SMTP over TLS, of zonder versleuteling voor oude toestellen). Voor een oud toestel stel je op het tabblad Verbinding van dat toestel een uitzondering in, in plaats van alles te verlagen.
  • Algemeen: taal, bewaartermijn van het logboek, maximale berichtgrootte, verbindingen per adres en je interne domeinen. Wijzigingen gelden meteen.
  • Back-up: download de toestellen, regels en instellingen als bestand en herstel ze later, bijvoorbeeld op een andere server. Het Microsoft-secret en de beheerderswachtwoorden zitten er bewust niet in.
  • Beveiliging: meerdere gebruikers (Beheerder of Alleen lezen), enkel bepaalde netwerken toelaten om de interface te openen, en de afmeldtijd. Bij Account zet je tweestapsverificatie aan: een code uit een app, met herstelcodes voor als je je telefoon kwijtraakt.

Buitengesloten? Op de server herstelt dit commando de toegang: docker exec office-smtprelay /office-smtprelay user passwd admin (nieuw wachtwoord), ... user reset-2fa NAAM (tweestaps uit) of ... user reset-access (netwerkbeperking weg).

8. Netwerk en HTTPS

  • Sta de SMTP-poort enkel toe vanaf de IP-adressen van je toestellen (firewallregel). De relay controleert zelf ook het bron-IP.
  • Deze webinterface spreekt gewone HTTP. Zet er een reverse proxy voor die HTTPS afhandelt en stel SMTPRELAY_TRUST_PROXY=true in, zodat het echte client-IP en de HTTPS-status gebruikt worden.

9. Het client secret vernieuwen

Verloopt het secret, dan stopt alle mail. Het dashboard waarschuwt je 30 dagen vooraf. Vernieuwen zonder onderbreking:

  1. Entra → App registrations → office-smtprelay → Certificates & secrets → New client secret, en kopieer de Value.
  2. Vul het nieuwe secret en de nieuwe vervaldatum in op de pagina Microsoft 365 en klik op Verbinding controleren.
  3. Verstuur een testmail. Werkt die, verwijder dan het oude secret in Entra.
