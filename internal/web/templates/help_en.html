How it works

Devices on your network (printers, scanners) send mail to this relay with a fixed IP address and a username and password. The relay forwards the mail to Microsoft 365 through the Microsoft Graph API using an app registration. No Microsoft password is stored on any device, and Security Defaults can stay on.

Step-by-step overview

  1. Create the Microsoft Entra app (about 10 minutes)
  2. Enter the values and check the connection
  3. Provide a sender mailbox
  4. Limit which mailboxes the app can send as (recommended)
  5. Wait about 5 minutes
  6. Send a test mail
  7. Add and configure the device
  8. Rules per device (optional)
  9. Administration, notifications and security
  10. Network and HTTPS
  11. Renew the client secret in time

Something wrong? See Troubleshooting or open the Logs page: Microsoft errors are listed there with an explanation.

1. Create the Microsoft Entra app

You need an account that can create app registrations and grant admin consent (Application Administrator or Global Administrator). No Azure subscription and no extra licence are needed.

Option A: in the portal

  1. Open entra.microsoft.com → Entra ID → App registrations → New registration.
  2. Name: office-smtprelay. Supported account types: Single tenant. Redirect URI: leave empty. Select Register.
  3. From the overview page, copy the Application (client) ID and the Directory (tenant) ID.
  4. API permissions → Add a permission → Microsoft Graph → Application permissions → search Mail.Send, tick it, Add permissions. Do not add delegated permissions.
  5. Select Grant admin consent for ... and confirm. The Status column must show a green check ("Granted for ...").
  6. Certificates & secrets → Client secrets → New client secret. Choose an expiry (maximum 24 months).
  7. Copy the secret Value immediately. It is shown only once. Do not copy the Secret ID.

Option B: with the helper script

The script performs steps 1 to 7 above for you. It writes nothing to disk: the values are shown once on screen.

  1. Download Setup-EntraApp.ps1 to a Windows PC.
  2. Open a normal PowerShell window (not an embedded terminal: the sign-in window needs a parent window) and run:
Install-Module Microsoft.Graph.Applications -Scope CurrentUser   # once
.\Setup-EntraApp.ps1                    # interactive sign-in
.\Setup-EntraApp.ps1 -SecretMonths 12   # shorter secret lifetime
.\Setup-EntraApp.ps1 -SkipConsent       # create the app, grant consent yourself (see step 4)

Sign in with an administrator account and approve the requested permissions. If you get an execution policy error: Set-ExecutionPolicy -Scope Process Bypass in that same window.

2. Enter the values and check the connection

  1. Open the Microsoft 365 page.
  2. Enter the Tenant ID, Application (client) ID, the client secret and the expiry date, then press Save. The expiry date is optional, but with it the dashboard warns you 30 days before the secret expires.
  3. Press Check connection. Green means Microsoft accepts the three values. It does not yet prove that sending mail is allowed.

3. Provide a sender mailbox

  • The sender address of a device must be an existing mailbox in your tenant, for example printer@yourdomain.com.
  • A shared mailbox is enough and needs no licence (up to 50 GB). Sign-in does not have to be enabled on it and neither does SMTP AUTH: the relay never signs in as that mailbox.
  • Sent messages end up in the mailbox's Sent Items. With lots of mail it can fill up: set a retention policy if needed.
  • Make sure SPF, DKIM and DMARC for your domain are in place, as for any other outgoing mail.

Create a shared mailbox in the Exchange admin center (Recipients → Mailboxes → Add a shared mailbox) or in Exchange Online PowerShell:

Connect-ExchangeOnline
New-Mailbox -Shared -Name "Printer" -DisplayName "Printer" -PrimarySmtpAddress printer@yourdomain.com

4. Limit which mailboxes the app can send as (recommended)

Without a limit, Mail.Send (application permission) lets the app send as any mailbox in your tenant. If the secret leaks, someone could send as anyone in your organisation. Exchange Online RBAC for Applications limits it to the mailboxes you choose. For a small tenant with a trusted network you may skip this step.

You also need the Exchange Administrator role. Find the service principal Object ID in Entra under Enterprise applications → office-smtprelay → Overview (note: not the Object ID of the app registration).

  1. Create a mail-enabled security group (for example smtp-relay-senders) in the Exchange admin center and add the sender mailbox(es) as members.
  2. Run this in Exchange Online PowerShell, adjusting the values:
Connect-ExchangeOnline

$appId = '<Application (client) ID>'
$spId  = '<Object ID of the ENTERPRISE APPLICATION (service principal)>'

# 1. Register the service principal in Exchange
New-ServicePrincipal -AppId $appId -ObjectId $spId -DisplayName 'office-smtprelay'

# 2. Create a scope with the allowed mailboxes
$group = Get-DistributionGroup 'smtp-relay-senders'
New-ManagementScope -Name 'SmtpRelaySenders' `
  -RecipientRestrictionFilter "MemberOfGroup -eq '$($group.DistinguishedName)'"

# 3. Allow the app to send mail only for that scope
New-ManagementRoleAssignment -App $spId -Role 'Application Mail.Send' -CustomResourceScope 'SmtpRelaySenders'

# 4. Verify (wait a few minutes if needed)
Test-ServicePrincipalAuthorization -Identity $spId -Resource printer@yourdomain.com        # InScope = True
Test-ServicePrincipalAuthorization -Identity $spId -Resource someone-else@yourdomain.com   # InScope = False
  1. Then revoke the tenant-wide Graph consent so that only the scoped Exchange assignment applies: Entra → Enterprise applications → office-smtprelay → Permissions → remove the consent for Mail.Send. (If you created the app with the script, use -SkipConsent next time.)

5. Wait about 5 minutes

New consent and permissions do not take effect immediately at Microsoft. Allow about 5 minutes, sometimes up to 30 minutes for Exchange role changes. A test mail that fails right after setup does not mean something is wrong: wait a little and try again.

6. Send a test mail

  1. Open the Test mail page.
  2. Use the mailbox from step 3 as sender and your own address as recipient. Later, also try an external address.
  3. Check that the mail arrives and does not land in junk.
  4. Failed? The error is shown on screen and on the Logs page (device "web UI"), with an explanation of what to do.

The test mail goes straight to Microsoft, so it tests the Microsoft side, not the device.

  3. Enter these settings on the device:

By default the relay uses a self-signed certificate. If the device refuses it, turn off certificate checking on the device or provide your own certificate. Very old devices that cannot do TLS 1.2 need the server setting SMTPRELAY_TLS_MIN.

Rules per device (optional)

The relay is not an open relay: a device needs a known IP address and must sign in. On top of that you can set extra rules per device under Clients → Rules. Nothing is required: a device without rules works exactly as before.

  • Sender: allow only certain addresses, or rewrite the sender to a single address. Rewriting never refuses and is ideal for printers that cannot set their sender.
  • Recipients: only internal addresses (your own domains), or your own list. A hijacked device then cannot send spam outside.
  • Limits: messages per hour and per day, recipients per message, maximum size. When exceeded the message is deferred, or the device is blocked for a few minutes.
  • Message changes: a fixed Reply-To address and a subject prefix.
  • Emergency stop on the dashboard: pauses all sending at once. Devices retry later.

How to do it safely: set a new rule to Test mode first. Violations are then only logged (Logs, filter Rule hits) and nothing is blocked. If after a few days the printer keeps to the rule, switch it to On.

Administration, notifications and securing the interface

  • Notifications: a short e-mail for Microsoft 365 problems, a secret about to expire, a blocked device or a pause. Off by default.
  • Connection: replace the TLS certificate (upload one or have a new self-signed one created), the oldest accepted TLS version, and extra ports (SMTP over TLS, or without encryption for old devices). For an old device set an exception on its Connection tab instead of lowering everything.
  • General: language, log retention, maximum message size, connections per address and your internal domains. Changes apply at once.
  • Backup: download the devices, rules and settings as a file and restore them later, for example on another server. The Microsoft secret and the administrator passwords are deliberately not included.
  • Security: several users (Administrator or Read-only), allow only certain networks to open the interface, and the sign-out time. Under Account you switch on two-step verification: a code from an app, with recovery codes in case you lose your phone.

Locked out? On the server these commands restore access: docker exec office-smtprelay /office-smtprelay user passwd admin (new password), ... user reset-2fa NAME (two-step off) or ... user reset-access (remove the network restriction).

8. Network and HTTPS

  • Allow the SMTP port only from the IP addresses of your devices (firewall rule). The relay also checks the source IP itself.
  • This web interface speaks plain HTTP. Put a reverse proxy in front of it that handles HTTPS and set SMTPRELAY_TRUST_PROXY=true, so the real client IP and the HTTPS status are used.

9. Renew the client secret

When the secret expires, all mail stops. The dashboard warns you 30 days ahead. To renew without interruption:

  1. Entra → App registrations → office-smtprelay → Certificates & secrets → New client secret, and copy the Value.
  2. Enter the new secret and the new expiry date on the Microsoft 365 page and press Check connection.
  3. Send a test mail. If it works, delete the old secret in Entra.

Troubleshooting

MessageMost likely cause
401 / invalid_clientWrong or expired secret, or the Secret ID was entered instead of the Value.
AADSTS700016Wrong client ID or tenant ID.
403 / ErrorAccessDeniedAdmin consent missing, the sender is outside the RBAC scope, or the permissions are not applied yet (wait 5 to 30 minutes).
404 / MailboxNotEnabledForRESTAPIThe sender address is not a mailbox in this tenant, or the mailbox is not synchronised yet.
429Microsoft is throttling. The relay retries later.
Mail arrives but lands in junkCheck SPF, DKIM and DMARC for your domain.
Device is refusedSee Logs: wrong IP address, wrong password, or authentication is off on the device.
